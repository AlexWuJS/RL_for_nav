# 脚本运行说明

当前分支只保留 DSAC+MPPI 相关流程。默认进入内层工程目录：

```bash
cd ~/RL_car/RL_car
```

## 训练 DSAC

```bash
python -m scripts.train.train_dsac \
  --model-name dsac_high_level \
  --control-mode high_level_frenet \
  --dynamics-model first_order \
  --curriculum auto \
  --total-timesteps 300000 \
  --log-interval 1000 \
  --episode-log-interval 100
```

默认输出：

```text
data/dsac_high_level/models/best_model
data/dsac_high_level/models/final_model_dsac
data/dsac_high_level/logs/
data/dsac_high_level/logs/tensorboard/
```

训练过程中终端会定期输出表格汇总。`--log-interval` 控制按环境 step 输出和写入 TensorBoard 的频率，`--episode-log-interval` 控制按 episode 输出汇总表的频率，默认每 100 个 episode 输出一次；设为 0 可以关闭终端 episode 汇总。

查看 TensorBoard：
在文件夹中打开终端
```bash
tensorboard --logdir data/dsac_high_level/logs/tensorboard --port 6006
```

然后在浏览器打开：

```text
http://localhost:6006
```

重点看 `rollout/*`、`train/*` 和 `curriculum/*`。

详细说明见 `docs/train_dsac.md`。

## 课程学习阶段

## USV 动力学模型

默认使用 `--dynamics-model first_order`，对应简化 USV 平面运动模型：

```text
状态: x, y, psi, u, r
控制输入: u_cmd, r_cmd
u_dot = (u_cmd - u) / T_u
r_dot = (r_cmd - r) / T_r
x_dot = u cos(psi)
y_dot = u sin(psi)
psi_dot = r
```

当前默认参数：

```text
dt = 0.1 s
u_cmd in [0, 1.5]
r_cmd in [-0.6, 0.6]
T_u = 0.6
T_r = 0.4
|delta u_cmd| <= 0.15
|delta r_cmd| <= 0.12
```

环境 `info` 会输出当前位姿、当前速度、Frenet `s,d`、heading error、remaining path 和 lookahead point；MPPI rollout 使用同一套一阶滞后动力学进行预测。`ideal` 仍可用于调试，`inertia` 会兼容映射到 `first_order`。

## Lookahead Point 局部目标

默认 `lookahead_distance = 3.0m`。环境会在全局 Frenet 参考线上取当前投影进度前方的中心线点：

```text
s_lookahead = min(s + 3.0, path_length)
p_lookahead = frenet_to_cartesian(s_lookahead, 0)
```

RL 观测中会加入船体坐标系下的 `lookahead_body_x, lookahead_body_y`，因此观测维度从 `400 + 4` 变为 `400 + 6`。已有旧 DSAC 模型的 `observation_dim` 不兼容该新观测，需要重新训练。

MPPI 的 planner state 也包含 `lookahead_point`，普通 MPPI rollout 会额外考虑预测轨迹末端到局部目标点的距离；最终成功条件仍由全局终点和 Frenet 横向误差决定。

训练命令中使用：

```bash
--curriculum auto
```

表示启用自动课程学习。当前实现一共有 5 个阶段，编号为 `0` 到 `4`。阶段越高，起终点采样范围、目标距离和路径曲率越大，训练难度越高。

| 阶段 | 采样范围 | 起终点距离 | 路径曲率偏移 | 训练重点 |
| --- | --- | --- | --- | --- |
| 0 | 8 m | 2-5 m | 0.0 | 短距离直线路径，先学会稳定前进和跟线 |
| 1 | 12 m | 4-8 m | 0.8 | 中距离、轻微曲线路径，提升路径跟踪 |
| 2 | 14 m | 5-10 m | 1.4 | 更长路径和更明显曲率，开始学习提前调整 |
| 3 | 18 m | 6-14 m | 2.0 | 大范围曲线路径，强化全局绕行倾向 |
| 4 | 20 m | 4-28 m | 2.5 | 完整随机难度，用于最终泛化训练 |

当前代码里，课程阶段主要控制 `ros_env.py` 中的起点、终点和 Frenet 参考路径曲率。障碍物本身仍主要来自 Gazebo world，例如 `src/ros/urdf02_gazebo/worlds/box_house_2.world`，还没有按课程阶段动态切换不同障碍布局。

自动切换逻辑在 `dsac_mppi/envs/curriculum.py` 中。每个 episode 结束后会记录一次：

- 是否成功到达目标：`is_success`
- 是否碰撞：`is_collision`
- 当前 Frenet 横向误差：`frenet_d`
- 最小激光距离：`min_laser_dist`

课程管理器会统计最近 50 个 episode，满足下面三个条件才升级到下一阶段：

| 指标 | 升级条件 |
| --- | --- |
| 成功率 | `success_rate >= 0.8` |
| 碰撞率 | `collision_rate <= 0.1` |
| 平均横向误差 | `mean_abs_frenet_d <= 1.5` |

升级后会清空最近 50 个 episode 的统计窗口，从新阶段重新累计。当前实现只会升级，不会自动降级；如果指标不达标，就继续停留在当前阶段。`--curriculum off` 会直接使用阶段 4 的完整随机难度。

训练时可以在终端表格和 TensorBoard 里看课程状态：

```text
curriculum/stage
curriculum/success_rate
curriculum/collision_rate
curriculum/mean_abs_frenet_d
curriculum/mean_min_laser_dist
```

## 评估 DSAC+MPPI

```bash
python -m scripts.test.compare_dsac_mppi \
  --model data/dsac_high_level/models/best_model \
  --mode dsac_rl_driven_mppi \
  --run-name dsac_rlmppi_eval \
  --plot
```

可用模式：

- `dsac`
- `pure_mppi`
- `dsac_rl_driven_mppi`
- `dsac_rl_driven_mppi_no_hss`
- `dsac_rl_driven_mppi_fixed_sigma`
- `dsac_rl_driven_mppi_no_q`
- `ablation_dsac_rlmppi`

评估结果默认保存到：

```text
data/dsac_high_level/eval/<run-name>/
```

详细说明见 `docs/evaluate_dsac_mppi.md`。

## 无 RL 参考线跟踪验证

这个脚本用于验证 USV 一阶滞后动力学、Frenet 参考线输出和简单 lookahead 控制闭环是否正常，不加载 DSAC，也不启用 MPPI。

Gazebo 已启动后运行：

```bash
python -m scripts.test.run_reference_tracker \
  --start=-8,-16 \
  --goal=8,-16 \
  --yaw=0.25 \
  --max-steps 300 \
  --lookahead 3.0 \
  --log-every 1
```

如果在 `scripts/test` 目录下直接运行脚本，也同样使用等号形式：

```bash
python run_reference_tracker.py \
  --start=-8,-16 \
  --goal=8,-16 \
  --yaw=0.25 \
  --max-steps 300 \
  --lookahead 3.0 \
  --log-every 1
```

期望现象：

```text
Frenet s 总体增加
Frenet d 不发散
heading error 后半程小于前半程
remaining path 逐渐减少
最终 remaining path 接近 0.45m 以内
```

默认 trace 保存到：

```text
data/reference_tracking/gazebo_reference_tracking_trace.csv
```

## 怎么验证项目能不能运行

建议按这个顺序排查，先跑不依赖 Gazebo 的检查，再跑 ROS/Gazebo 联调。

### 1. 代码和单元测试

```bash
cd ~/RL_car/RL_car

python -m py_compile \
  dsac_mppi/algorithms/dsac.py \
  dsac_mppi/controllers/mppi_dbas.py \
  dsac_mppi/controllers/rl_driven_mppi.py \
  dsac_mppi/envs/curriculum.py \
  dsac_mppi/envs/ros_env.py \
  scripts/train/train_dsac.py \
  scripts/test/compare_dsac_mppi.py \
  scripts/test/run_dsac_mppi.py

python -m unittest discover -s tests
```

如果显示 `OK`，说明 Python 模块、导入路径和核心单元测试是通的。

### 2. catkin 编译

```bash
catkin_make --source src/ros
source devel/setup.bash
```

如果没有 CMake/package 报错，说明 ROS 包结构基本可用。

如果前一次编译失败导致 `devel/setup.bash` 不存在，先重新编译成功再 source。CMake 4.x 环境下如果遇到旧版兼容报错，可以清理失败产物后重试：

```bash
rm -rf build devel
catkin_make --source src/ros
source devel/setup.bash
```

### 3. 启动 Gazebo

```bash
roslaunch urdf02_gazebo RL_car.launch
```

另开终端检查：

```bash
rostopic list | grep -E '/scan|/cmd_vel|/gazebo/model_states'
rosservice list | grep -E '/gazebo/set_model_state|/gazebo/get_model_state|/gazebo/spawn_sdf_model'
```

这些 topic/service 都存在，`ros_env.py` 才能正常和仿真通信。

### 4. DSAC+MPPI 实跑

Gazebo 已启动后运行：

```bash
python -m scripts.test.run_dsac_mppi \
  --model data/dsac_high_level/models/best_model \
  --mode dsac_rl_driven_mppi \
  --max-steps 200 \
  --log-every 10
```

如果终端持续打印 step/reward/info，且 Gazebo 中机器人运动，说明运行链路基本通了。

### 5. 短评估

```bash
python -m scripts.test.compare_dsac_mppi \
  --model data/dsac_high_level/models/best_model \
  --mode dsac \
  --episodes 1 \
  --max-steps 200 \
  --run-name verify_dsac
```

正常会生成：

```text
data/dsac_high_level/eval/verify_dsac/
```
